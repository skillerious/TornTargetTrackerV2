    • Setup and onboarding

    Ship a stable configuration

    Follow these fundamentals before you rely on the tracker during chains or raids.

    Configuration

    Five steps to a clean start

    ~3 minutes
    1. Connect API keysAdd your Torn key (required) and TornStats key (optional for loot timers). Validate both to confirm connectivity.
    2. Add targetsUse Add Target for single entries or Bulk Import to paste IDs/URLs. Start with a small batch.
    3. Group with intentCreate focused groups: Farm, Do Not Attack, Faction, Chain. Keep All Targets for audits.
    4. Tune refreshBegin with Auto Refresh every 30-60 seconds, Concurrent Requests at 2-3, and API Rate Limit below your cap. Raise cautiously.
    5. Enable notificationsTurn on desktop + sound. Watch critical targets so their status changes always alert you.

    Connections

    Keep signals green

    • Use Run connection check to validate Torn + TornStats after key changes.
    • If STS is red, confirm TornStats permissions include Public and wait 60 seconds.
    • Drop concurrency to 2 if you see spikes; slowly increase once stable.
    • Pause Auto Refresh while importing to avoid overlapping calls.

    Safety net

    Backups and restores

    • Keep Auto Backup on; point it to a synced folder for redundancy.
    • Run Backup now before bulk imports, deletes, or mass edits.
    • Export before experimenting; re-import a small subset to validate format.
    • For a hard reset: export, wipe, import the clean file, verify counts.

    Daily operations

    Run smooth chains and sweeps

    Lean workflows for triage, chains, and loot without burning rate limits.

    Triage

    Stay ahead of timers

    • Filter to Attackable first, then scan Hospital/Jail for upcoming windows.
    • Collapse groups you do not need during chains to speed up scanning.
    • Use notes for opener/finisher plans and consumables used.

    Chain discipline

    Use Attack Tracker

    • Enable the tracker on your filtered list before spending energy.
    • Mark high-risk targets as watched so alerts punch through other views.
    • Reset the tracker after chains to clear stale progress.

    Intel hygiene

    Keep data fresh

    • Refresh profiles after travel/jail release before attacking.
    • Use favorites + watched flags to sort critical targets to the top.
    • Clean notes weekly; remove stale tactics and add outcomes.

    Recovery

    Fix issues fast

    If something feels off, try these focused playbooks.

    Statuses

    Not updating

    Quick fixes
    • Validate Torn key; ensure permissions include "Public".
    • Open Connection Status; confirm NET, API, STS are green.
    • Set Concurrent Requests to 2 and retry Refresh All.
    • Increase Refresh Interval to 45-60 seconds temporarily.

    Visibility

    Targets look missing

    Quick fixes
    • Clear search; set Filters to All.
    • Select All Targets; expand collapsed sections.
    • If recently deleted, re-import from your latest backup/export.

    Notifications

    Alerts are silent

    Quick fixes
    • Enable desktop + sound in Notifications.
    • Toggle Notify only monitored off to test.
    • Watch a target, change its status, and confirm a toast.

    Rate limits

    API penalties

    Quick fixes
    • Raise Refresh Interval; keep Concurrent Requests at 2-3.
    • Pause Auto Refresh for 60 seconds to clear penalties.
    • Avoid running bulk imports alongside manual refreshes.

    Reliability

    Alerts and data safety

    Keep signals meaningful and make sure your data stays recoverable.

    Notifications

    Keep alerts actionable

  • Monitored-only mode: Use this to quiet noise; watch only high-priority targets.
  • Status-to-action mapping: Hospital/Jail expiring soon -> prep energy; Traveling -> set a reminder to check landing.
  • Sound discipline: Keep sound on for attackable; off for informational signals.
  • Recovery plan: If alerts fail, follow the notification troubleshooting steps before restarting.

    • Data safety

    Backups, imports, and resets

  • Auto backup: Keep it on; choose a cadence that matches your change volume.
  • Pre-change backup: Run Backup now before bulk deletes, imports, or restructures.
  • Cloud copy: Point backups to a synced folder (Drive/Dropbox/OneDrive/etc.).
  • Safe restore: Export current targets, then import the backup; verify counts and groups.
  • Hard reset plan: Export, wipe, re-import a clean file; keep one copy offline.

    Glossary and playbook

    Shared language

  • Watched: A target marked for priority alerts; combine with favorites for sorting.
  • Coming Soon: Hospital/Jail timers nearing completion; prep energy and consumables.
  • Attack tracker: Progress tracker tied to your current filters; reset between runs.
  • Refresh hygiene: Keep intervals modest and concurrency low to preserve rate limits.
  • Chain mode: Pre-plan targets, refresh intel, and pin notes with opener/finisher sequences.
  • Safety net: Backups + exports before any destructive action; verify after restore.
    • When should I export vs. back up?
    Use backups for quick restores and exports for portable copies or audits. Do both before risky edits.
    How do I stay under rate limits?
    Keep refresh at 30-60s, set concurrency to 2, pause Auto Refresh during imports, and retry after a 60s cool-down if penalized.
